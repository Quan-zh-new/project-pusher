# Libra 数据回收常用查询

用于一次数据回收中按“实验名称 -> 实验/版本 -> 指标组/指标 -> 数据 -> 原生截图”完成读取。以下命令均为只读查询；截图仅写入本地 `data/assets/`，不修改实验或报告。

## 输入与约定

先替换以下变量。`EXPERIMENT_VERSION_ID` 是本次要单独回收的实验版本；`BASE_VERSION_ID` 是实验详情中返回的基准版本。多个实验版本应逐个执行数据查询和截图，不应把不同版本的结果混在一行。

```bash
LIBRA_CLI="/path/to/project-pusher/.venv-libra-cli/bin/libra-cli"
EXPERIMENT_NAME="<实验名称>"
EXPERIMENT_ID="<步骤 1 返回的实验 ID>"
EXPERIMENT_VERSION_ID="<步骤 2 返回的实验版本 ID>"
BASE_VERSION_ID="<步骤 2 返回的基准版本 ID>"
METRIC_GROUP_NAME="<指标组名称>"
METRIC_GROUP_ID="<步骤 3 返回的指标组 ID>"
METRIC_NAME="<指标名称>"
METRIC_ID="<步骤 3 返回的指标 ID>"
# 必须在步骤 2 按当前运行时的日期计算；不得手填、沿用历史日期或按“最新有数据”猜测。
DATA_DATE="<步骤 2 计算出的 endDate>"
```

## 1. 按实验名称定位实验 ID

```bash
"$LIBRA_CLI" experiment list \
  --search-keyword "$EXPERIMENT_NAME" \
  --json
```

从命中结果中确认实验名称、所属应用和状态后记录 `experiment_id`。名称不唯一时，不要猜测；保留候选并由当前任务 Context 或用户确认目标实验。

## 2. 查询实验元数据和版本

```bash
"$LIBRA_CLI" experiment get \
  --experiment-id "$EXPERIMENT_ID" \
  --with versions,analysis \
  --json
```

从返回 JSON 的 `data.data` 中记录：

- `versions`：记录基准版本 `BASE_VERSION_ID` 和每个需要单独回收的 `EXPERIMENT_VERSION_ID`；
- `experiment.timing.start_time`、`experiment.timing.end_time`：Unix 秒级时间戳，用于计算本次日级查询窗口。

### 日级查询日期计算

`metrics report-data` 的 `--start-date` 与 `--end-date` 必填。本 Skill 不让模型自行按“今天”“实验结束日”或“最新有数据”猜测日期；先将上述时间戳转换为 **上海时区** 日期，并在当前 Run 按下面的规则计算：

```text
rawStart = 上海时区的 timing.start_time 日期
rawEnd = 上海时区的 timing.end_time 日期

startDate = timing.start_time 不是 00:00:00
  ? rawStart + 1 天
  : rawStart

experimentEndDate = timing.end_time 不是 00:00:00
  ? rawEnd - 1 天
  : rawEnd

endDate = min(上海当前日期 - 1 天, experimentEndDate)
DATA_DATE = endDate
```

这保证日级数据只覆盖实验运行期间的完整自然日，并与本项目数据回收的默认报告查询截止日保持一致。`startDate` 是完整自然日窗口的起点；本次单日 `report-data` 和 `snapshot` 均必须使用同一对起止日期。不要把 `analysis.suggestion.end_date` 当作 `DATA_DATE`：它是分析建议窗口，可能晚于当前可查询日期。

若 `startDate` 或 `endDate` 为空，或 `endDate < startDate`，停止数据查询并报告没有可查询的完整自然日；不要改用任意历史日期。默认日期查询无数据时，也先如实保留“默认日期无数据”的结果；只有用户明确要求回溯日期时，才以用户指定日期重新查询，并将其标为回溯日期，不能替代 `DATA_DATE`。

## 3. 按指标组和指标名称定位 ID

先查指标组：

```bash
"$LIBRA_CLI" metrics search \
  --experiment-id "$EXPERIMENT_ID" \
  --metric-group-key "$METRIC_GROUP_NAME" \
  --top 5 \
  --json
```

再查指标：

```bash
"$LIBRA_CLI" metrics search \
  --experiment-id "$EXPERIMENT_ID" \
  --metric-key "$METRIC_NAME" \
  --top 5 \
  --json
```

记录选中结果的 `metric_group_id` 和 `metric_id`。指标名称可能跨指标组重复，需确认指标命中归属的 `metric_group_id` 与前一步选中的 `METRIC_GROUP_ID` 一致；不一致时继续选择同组候选，而不是把名称相同的指标跨组拼接。

## 4. 查询指定日期和版本的数据

使用 `report-data` 读取标准报表数据。`--selected-metric-ids` 限定本次指标；`--base-vid` 和 `selected_vids` 明确本次基准/实验版本，避免默认版本范围导致结果混合。

```bash
"$LIBRA_CLI" metrics report-data \
  --experiment-id "$EXPERIMENT_ID" \
  --metric-group "$METRIC_GROUP_ID" \
  --start-date "$DATA_DATE" \
  --end-date "$DATA_DATE" \
  --period-type d \
  --selected-metric-ids "$METRIC_ID" \
  --base-vid "$BASE_VERSION_ID" \
  --extra-query "{\"selected_vids\":\"$EXPERIMENT_VERSION_ID\"}" \
  --json
```

逐个 `EXPERIMENT_VERSION_ID` 执行并在结果中保留：实验 ID、基准版本 ID、实验版本 ID、指标组 ID、指标 ID、请求日期，以及实际返回的数据日期。若请求日期没有数据，可再以明确的新日期重查；最终输出必须标注实际数据日期，不能把较早日期表述为请求日期。

## 5. 导出同一范围的原生表格截图

`metrics snapshot` 生成 Libra 原生表格截图。输出必须位于 `data/assets/`，文件名包含实验、指标组、指标、日期和实验版本，便于后续 Artifact/文档引用。

```bash
OUTPUT="data/assets/libra-exp${EXPERIMENT_ID}-group${METRIC_GROUP_ID}-metric${METRIC_ID}-${DATA_DATE}-vid${EXPERIMENT_VERSION_ID}.png"

"$LIBRA_CLI" metrics snapshot \
  --screenshot-type table \
  --flight-id "$EXPERIMENT_ID" \
  --group-id "$METRIC_GROUP_ID" \
  --selected-metric-ids "$METRIC_ID" \
  --start-date "$DATA_DATE" \
  --end-date "$DATA_DATE" \
  --versions "$EXPERIMENT_VERSION_ID" \
  --base-version-id "$BASE_VERSION_ID" \
  --combine 0 \
  --output "$OUTPUT"

test -s "$OUTPUT" && printf 'snapshot: %s\n' "$OUTPUT"
```

历史成功的 `execute_cli` 调用已验证 `metrics snapshot --screenshot-type table --flight-id ... --group-id ... --output data/assets/...png` 的本地导出路径。这里额外传入日期、指标和版本范围，以使截图和第 4 步的数据查询保持同一筛选条件。
